# ADR-0002: The `v1` contract

## Context

The API is anonymous, read-only and meant to outlive its first consumer
(`docs/implementation-plan-public-api.md` in `one-piece-api`, D4-D9, D12). Its callers are
browsers and other programs we do not control, so what it says must change rarely and
never break.

## Decision

- **Paths:** `GET /v1`, `/v1/languages`, `/v1/{lang}/devil-fruit-types[/{idOrSlug}]`. Version
  first, language right after: an unknown language is a `404`, never a default.
- **Within `v1`, fields and endpoints are only added.** CI compares the generated
  `openapi/openapi.yaml` with the committed `openapi/v1-baseline.yaml` and fails on a breaking
  change (oasdiff; see the R7 addendum).
- **Identifier:** the content UUID; the slug of the romaji is accepted on the same path
  (a UUID is recognised by its format). An old slug answers `301` with the current slug as
  a *relative* `Location`, so it holds behind any prefix the gateway strips.
- **Bodies:** plain JSON, camelCase, every field always present (`null` when missing),
  dates in ISO 8601 UTC to the second, no absolute URL. Never the version number, status,
  author or anything else of the workflow.
- **Lists:** `page` (0-based), `size` (default 20, capped silently to 100, both from
  configuration), `sort=field[,direction]` over a closed set, `q` (100 characters at
  most). Unknown parameters are ignored; a page past the last is an empty `200`.
- **Errors:** Problem Details with `errorCode` (`one-piece-exception`): `400
  VALIDATION_FAILED`, `404 LANGUAGE_NOT_AVAILABLE` (checked before the content), `404
  CONTENT_NOT_FOUND` (unknown, never published or retired: indistinguishable on purpose),
  `404 NOT_FOUND`, `405 METHOD_NOT_ALLOWED`, `500 INTERNAL_ERROR`. `429` comes from the
  gateway.
- **Browser:** CORS `*` for `GET`/`HEAD`, no credentials; `X-Content-Type-Options: nosniff`
  on every answer; gzip above 1 KB. `Content-Type` is `application/json` with no
  `charset`: JSON is UTF-8 by definition (RFC 8259).
- **Contract in code:** the spec is generated by springdoc, committed and guarded by
  `OpenApiSpecTest`; the Bruno collection is generated from it. No Swagger UI.

## Alternatives considered

- `?lang=` or `Accept-Language`: need a default and fragment the cache.
- HAL or JSON:API: weight for no consumer that asked for it.
- A `410 Gone` for retired contents: it can be restored, and telling it apart would widen
  what the views expose.

## Consequences

- A change a client could notice needs a `v2`, not an edit.
- A slug shaped like a UUID would be read as an id; slugs come from romaji, so it cannot
  happen in practice.
- `/v3/api-docs` is served to anyone: the contract is public like the data.

## Addendum - Images without extension (WebP plan W2)

- **Exception to "only added":** `GET /v1/images/{id}.png` is replaced by `GET /v1/images/{id}`,
  with no alias. content-service now stores images as WebP (its ADR-0010), so a `.png` path would
  lie about the bytes; the format is the `Content-Type` (`image/webp`, `image/png` for rows
  stored before, converted in W5).
- **Why no `v2`:** no image URL had been published when the change was made (the only remote image
  was still in review), and the image ids change anyway when W5 re-encodes the PNG rows. No client
  can hold a `.png` address.
- oasdiff reports the removed path as breaking: accepted once, for this reason. The rule above
  stands for every later change.

## Addendum - The reader axis in `v1` (reveals plan R7, D2)

- **Second exception to "only added", taken once:** the reader axis (content-service ADR-0011,
  0012, 0013) changes the shape of existing fields:
  - epithets and aliases become `{value, former, discovered, ended}`; species, Devil Fruits,
    fruit users and relatives gain `former`, `discovered`, `ended`;
  - a membership is `{affiliation, former, periods[{role, marineRank, former, discovered, ended}]}`;
  - `description`, `advantages`, `disadvantages` become lists of `{text, discovered}`; an ended
    paragraph is not shown;
  - a character gains `gallery`; its `image` is the main portrait (workflow 3.5.1);
  - Character, Devil Fruit and Bounty gain `initialKnowledge` and `reveals`.
  A point is `{chapter, episode}` as numbers; `former` is derived from `ended`, never stored.
- **Why no `v2`:** one consumer (the frontend, same owner), no published client, the remote down
  when it ships. A `v2` beside `v1` would double every view and test for no reader.
- **Guard from now on:** oasdiff compares `openapi/openapi.yaml` with the committed
  `openapi/v1-baseline.yaml` on every push and PR. Before, it ran on PRs only, and work goes to
  `main` without PRs: the rule was never checked. A break is accepted only by a separate commit
  that copies the spec over the baseline, with an addendum here.
